# Night Owl 夜鹰

为 Chrome 打造的全站夜间模式扩展（Manifest V3）。所有功能均在浏览器本地运行，无账号、无服务器，
扩展自身不发出任何网络请求，数据不出本机。界面支持中 / 英双语（跟随浏览器语言）。

## 功能

- **全站夜间模式**：CSS 滤镜反色，图片 / 视频 / 画布自动还原原色（只比白天略暗一档，
  不受色温 / 灰度 / 亮度 / 对比度影响）
- **自动切换**：两种时间表
  - 跟随日出日落：填入经纬度（纯本地天文算法，不需要联网），支持自定义偏移；
    极昼极夜自动降级为固定时段
  - 固定时段：例如 19:00 – 07:00
- **定位辅助**：点「获取我的位置」自动填经纬度，并回显最近城市
  （内置 3300 城精简库，本地匹配，不联网反查）
- **手动切换**：popup 一键切换 自动 / 黑夜 / 白天。选「黑夜」或「白天」只是**临时覆盖**，
  到下一个日出/日落（或固定时段边界）会自动回到「自动」
- **站点三态**：popup 底部对当前网址可选 跟随自动 / 强制夜间 / 强制白天，
  分别对应「不落名单 / 始终夜间 / 始终白天」，随时可切回跟随自动
- **工具栏徽标**：黑夜时显示 ON，白天时显示 OFF
- **总开关最顶层**：设置页关闭「启用」后，popup 的昼夜模式与站点三态、快捷键全部暂不生效
  ——相关按钮会置灰并给出提示，重新开启后恢复
- **外观调节**：暗度、亮度、对比度、饱和度、色温（-100 冷 ↔ +100 暖）、黑白程度，
  设置页带实时预览；「高级」里另有媒体亮度（60–100%）
- **始终夜间 / 始终白天**（始终夜间 = 要变暗，始终白天 = 不变暗）
  - **始终白天**：这些网址保持原色，优先级最高
  - **始终夜间**：这些网址强制变暗，即使当前是白天时段
  - 都没进：跟随全局 自动 / 黑夜 / 白天
  - 支持 `*.example.com` 子域名通配与路径前缀；两个名单互斥，加一边会自动从另一边摘除
  - 设置页分两个独立区域，上半部分是已加入的网址（一行一个，可单独移除），
    下半部分输入框回车或点「确定」即录入；「站点规则」页还支持一键把当前站点加入任一名单
- **快捷键**：`Alt+Shift+D` 切换昼夜；站点加入 / 移出始终白天名单可在
  `chrome://extensions/shortcuts` 自行绑定
- **配置导入导出**：JSON 文件，带 schema 版本校验，可迁移到其他电脑
- **面板自动换肤**：popup 与设置页跟随当前生效的明暗自动切换配色（黑夜暗色、
  白天或总开关关闭时亮色），与徽标用的是同一套判定

## 安装（开发者模式）

1. 打开 `chrome://extensions`
2. 右上角开启「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录（`night-owl`）

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存设置到本地 |
| `tabs` | 向已打开的标签页同步状态 |
| `scripting` | 给「扩展加载前就已打开」的标签页补注入内容脚本 |
| `alarms` | 按时间表触发昼夜切换；面板落盘后作为信号通道唤醒后台 |
| `geolocation` | 一键填入所在位置的经纬度（仅设置页主动点击时触发） |
| `<all_urls>` | 对所有网站生效所必需 |

不申请 cookies、不申请网络请求类权限，扩展本身不发出任何网络请求。
定位只用浏览器给的经纬度，城市名由内置的本地城市库匹配得出，不会把坐标发给任何服务器。

## 兼容性

- **Chrome / Edge / Brave / Opera**：MV3 Service Worker，原生路径
- **Firefox 115+**：同一份包可直接加载（`browser_specific_settings` 已声明）
- 后台脚本带双路加载：`importScripts` 可用时走原生 Service Worker；
  若浏览器原生注册失败（`Service worker registration failed. Status code: 15`），
  自动退化为事件页（MV2 风格持久后台），不再反复弹报错

### 通信通道（重要，不要改回去）

**面板 ↔ 后台**只有两条通道，都不使用 `chrome.runtime.onMessage`：

1. `chrome.storage.local`：面板直接读写（`src/lib/store.js`），后台的
   `storage.onChanged` 承接「变更 → 刷徽标 → 重排闹钟 → 广播到所有标签页」。
2. `chrome.alarms` 信号闹钟：面板落盘后再把整份配置编码进 alarm name 发给后台，
   后台收到即采信，不回读 storage（本机回读有"写一拍滞后"，读到的可能是旧快照）。

为什么不用消息通道：在某些 Chrome 构建上，Service Worker 里的 `runtime.onMessage`
会注册失败（可在 `Secure Preferences` → `serviceworkerevents` 里实证：该集合里没有它），
而 `chrome://extensions` 不报任何错。一旦如此，所有「发消息给后台」的操作都会石沉大海 ——
表现就是**面板里的改动关掉再打开又变回原样**。

> 注意区分：**后台 → 页面**是另一跳，仍用 `chrome.tabs.sendMessage` 推 `nw:tick`，
> 页面侧由 `content.js` 的 `chrome.runtime.onMessage` 接收。这一跳失败也有兜底 ——
> 页面自己也监听 `chrome.storage.onChanged`，所以配置变更最终一定会收敛。

改动这一层前请先读 `src/lib/store.js` 顶部注释与 `tools/check.js` 的 `[9]` 段。

## 已知边界（filter 方案的固有特性）

- 地图、在线设计工具、PDF 查看器等依赖精确颜色的页面效果差，
  请加入**始终白天**名单（保持原色、不套滤镜）
- 页面使用 `position: fixed` 的吸顶导航在部分站点可能表现异常，
  可在「高级」中切换滤镜应用范围，或加入始终白天名单
- 本身已是深色主题的站点可交给「高级」里的**跳过深色站点**自动检测；
  检测不出来的（如跟随系统、只有局部深色的 SPA）用始终白天名单手动兜底
- 「保留图片与视频的原始色彩」开启时，媒体被精确还原（默认只比白天暗 8%，
  可在「高级 · 媒体亮度」调整），不受色温 / 灰度 / 亮度 / 对比度影响；
  关闭则图片跟随整页一起变暗。极鲜艳色可能因 CSS 滤镜的色域裁剪有难以察觉的微小差异

## 目录结构

```
night-owl/
├── manifest.json          # MV3 清单
├── _locales/              # en / zh_CN 文案
├── icons/                 # 16 / 48 / 128 图标
├── src/
│   ├── background.js      # Service Worker：排程、快捷键、徽标、广播
│   ├── content.js         # 页面渲染引擎（防白闪：sessionStorage 缓存 + 异步校准）
│   ├── inject.css         # 静态样式通道（运行时样式由 content.js 生成）
│   ├── lib/
│   │   ├── config.js      # 配置 schema、默认值、归一化校验
│   │   ├── sun.js         # NOAA 日出日落算法（纯本地计算）
│   │   ├── matcher.js     # 站点名单规则解析与匹配
│   │   ├── filter.js      # 滤镜构造（渲染与预览共用）
│   │   ├── store.js       # popup/options 直连 storage + 信号闹钟（不依赖 onMessage）
│   │   ├── cities.data.js # 内置 3300 城精简库（自动生成，仅设置页加载）
│   │   └── cities.js      # 经纬度 → 最近城市（本地最近邻匹配）
│   ├── popup/             # 工具栏弹窗
│   └── options/           # 设置页
└── tools/                 # 自检脚本 + 一次性排查产物
    ├── check.js           # 一键自检（唯一的测试入口）
    ├── make_icons.py      # 生成 16/48/128 图标（重做图标时才跑）
    ├── build_cities.js    # 从 GeoNames 构建城市库（离线跑一次）
    ├── badge.e2e.js       # 真机复现：真实 Chrome 加载扩展，验证徽标写入时序
    ├── e2e.js + e2e.html  # 历史排查产物：滤镜像素级验证
    │                      #   （硬编码了本机 agent-browser 路径，换机跑不通）
    ├── sim.js             # 历史排查产物：端到端模拟（其场景已被 check.js 覆盖）
    └── .cache/ shots/     # 城市库构建缓存与截图
```

改完代码后跑一次自检：

```bash
node tools/check.js
```

自检覆盖多个段落，其中几段专门守住「面板改了不生效」这类问题：

- `[8] broadcast`：任何主动操作都必须真的广播到标签页
- `[9] storage 直写通道`：用最小 DOM 夹具真跑一遍 popup，断言读得到、写得进、
  徽标同帧翻转、落盘后发信号闹钟，且全程不依赖任何消息通道
- `[10] preserveMedia 滤镜数学`：父级不许出现不可反向算子（`sepia` / `grayscale`），
  媒体子级必须逐项精确抵消父级
- `[11] content.js`：页面收到任何提醒消息都只回读 storage，陈旧消息不得把页面打回旧状态；
  并钉住「父级 `FILTER.build` 必须带 cfg」（漏传会让媒体还原失效）
- `[12] 面板换肤`：两套主题的 CSS 变量必须齐全

lib 模块同时兼容两种挂载方式：扩展里挂到 `globalThis.NW.*`，
node 下平铺到 `module.exports`，因此自检脚本和构建脚本可以直接 `require`。
